# MCP dashboard UI

The UI bundles the MIT-licensed `@openuidev/react-lang` runtime locally. It is not OpenUI's managed dashboard service and sends no data to that service; Copilot supplies the optional layout and all evidence comes from the MCP tool. Official references: [React runtime and examples](https://github.com/thesysdev/openui/tree/main/packages/react-lang), [OpenUI Lang](https://openui.com/docs/openui-lang), and [MCP Apps SDK](https://github.com/modelcontextprotocol/ext-apps).

Run `npm run build:dashboard` to create `dist-dashboard/mcp.html` and the generated `src/dashboard-html.generated.ts` export `dashboardHtml`. Server code imports `./dashboard-html.generated.js`; the normal npm build and the zero-install esbuild agent bundle embed the HTML. `node scripts/build-dashboard-ui.mjs --check` checks the generated module without writing. `ci:prepare` generates before agent bundling; `ci:check-generated` checks both.

The view expects an MCP Apps `ontoolresult` with `structuredContent` equal to the `cicd-optimizer/dashboard-metrics-v1` projection, or `{ metrics: projection, layout?: { sections: [...] }, pages?: { jobs, findings, gaps } }`. Each page is `{ offset: number, total: number, nextOffset: number | null }`. Each job may have `stepsTotal` and `nextStepOffset`, and each finding may have `evidenceTotal` and `nextEvidenceOffset`. Layout accepts 1–4 unique section names from `overview`, `jobs`, `attribution`, and `comparison`, in display order. Invalid layouts fall back to all sections and are visibly reported. This bounded JSON is converted locally to OpenUI Lang; model-provided HTML, scripts, tool names, URLs, or arbitrary OpenUI programs are never executed. No inference provider is invoked.

Before connecting, the view registers `ontoolinput`, `ontoolresult`, and `onhostcontextchanged`. It refreshes via `app.callServerTool({ name: "dashboard_metrics", arguments: originalArguments })`, pins `runAttempt` to the opening projection, and rejects later mismatched attempts. Job drilldown uses `jobId`; server paging uses `jobOffset`, `stepOffset`, `findingOffset`, `gapOffset`, and `evidenceOffset`. Step paging scopes to a job; evidence offset applies across returned findings because the contract has no finding selector. The server must authorize and implement these scoped requests and deliver the same projection contract. Without original tool input refresh and drilldown are disabled. The host supplies the light/dark theme; otherwise Clawpilot's query/system preference applies. Timeline bars use only valid reported intervals, and comparisons only returned data; missing data remains unknown and incomplete evidence is labeled rather than interpreted as zero.
